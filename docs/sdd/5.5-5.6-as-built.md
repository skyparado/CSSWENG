## 5.5 Follow-Up and Procedure Reminders Module

### 5.5.1 Description

This module tracks patients who need a follow-up, check-up, laboratory test, injection or procedure, and makes sure none is missed. The Doctor sets each task with a reason, due date and priority. The Follow-Up and Procedure List (S11) groups tasks as Overdue, Due, Booked, Done and Closed for the active clinic. The Secretary works the list: she calls patients, records each attempt in the Outreach Log (S12), books the visit, and closes the task.

Automated SMS and email reminders go out only to patients with active reminder consent for that channel. A background job (BullMQ) checks for due tasks every morning at 8:00 AM Manila time, and staff can also send a reminder for one task on demand. Reminder text names only the clinic and the due date, never the task type or clinical reason, because SMS and email are not secure channels under RA 10173. A task closes when its linked appointment is completed, or when staff record its completion, a decline, or after three failed contact attempts (unreachable).

## 5.6 Medications and Health Summary Module

### 5.6.1 Description

This module keeps each patient's current medications and allergies in one place and warns the Doctor before she records a medicine that conflicts with them. It is Doctor-only (Table 7-1); the Secretary cannot view or change medications or allergies. The combined health summary (current medications, allergies, active conditions and trends) is shown on S06 Patient Chart Summary, described in Section 5.3.

Every change to a medication saves a new version and keeps the earlier one, so the full dated history is never lost. Before a medication is saved, the system checks it against the patient's allergies and current medicines using a bundled drug and allergen reference. Each alert must be acknowledged before saving, and the acknowledged alerts are stored with that version. The reference records its version and who approved it, and can be replaced with the clinic's approved list without code changes.

At each visit the Doctor can mark the current medication list as reviewed. S10 shows whether the list was reviewed today, and each review is recorded in the audit trail.

## Additions for Sections 7.4 and 8.6

**7.4 Rights of the patient (add after the current paragraph).** Requests are recorded on the Patient Rights Requests screen as access, copy or correction, with how the request was received. Either staff role records a request; only the Doctor marks it completed or denied, with a required note on what was done or why. The patient's request and the Doctor's note are stored encrypted. The audit trail logs each request and decision (RIGHTS_REQUEST_RECORDED, RIGHTS_REQUEST_COMPLETED, RIGHTS_REQUEST_DENIED) without the free text. The Secretary sees only requests filed under her active clinic.

**8.6 Backup and recovery (add at the end).** Backups run daily at 2:00 AM and the retention purge at 3:30 AM Manila time. The free hosting plan used for the demo sleeps when idle, so the Doctor can also start a backup, the retention purge or the reminder check from the System Jobs panel on S17 Reports. Each backup is encrypted with AES-256-GCM before upload, and each backup and purge outcome (completed or failed) is written to the audit trail and shown in the panel. The restore script decrypts a chosen backup and restores it into a new, empty database, refusing the live database or one that already has tables, then compares every table's row count with the live database. An automated round-trip test (pg_dump, encrypt, decrypt, pg_restore, compare row counts) runs with the integration suite.
